# Verification Checklist coverage (0.20.0)

Maps each item of the 0.20.0 release spec's **Verification Checklist** to the automated test that proves it. Paths are relative to `packages/<package>/src/`; test names are quoted as `describe › it`. Integration tests (`service/src/test/*-integration.test.ts`) run against a real Qdrant (CI: `.github/workflows/integration.yml`, `QDRANT_REQUIRED=true`) in throwaway `jeeves_watcher_it_*` collections, with the stub source server (`test/harness/stubSource.ts`) and counted mock embeddings (`test/harness/countingProvider.ts`).

Titles containing `%s`, `%i` or `%j` are `it.each` templates, quoted as written in the source. Struck checklist items are deferred by Decision 15 and listed after the table. Rows 30–38 are the checklist items added by the pre-release review. Decision 18 (R1–R5) and the review resolutions (Decision 19) follow.

## Test hygiene

- Every integration collection is named `jeeves_watcher_it_<label>_<run>_<worker>_<nonce>` (`test/harness/qdrant.ts`); `assertTestCollection` refuses to create or drop anything else, and `assertTestQdrantUrl` refuses any Qdrant but the one global setup provisioned or guarded for this run (`test/harness/qdrant.test.ts` › "harness Qdrant URL guard › refuses %s", "names carry the run id, and only this run matches the sweep"; `test/harness/service.test.ts` › "refuses a config override naming a non-test collection", "refuses a config override naming another Qdrant"). `test/helpers.ts` and the file suites (`gitignore-integration.test.ts`, `test/legacyIntegration.ts`) use the same guarded names.
- `startServiceHarness` rolls back on a setup failure, dropping the collection it created (`test/harness/service.test.ts` › "drops the collection when setup fails after creating it").
- `test/globalSetup.ts` checks the throwaway instance with the same shared-instance guard as a configured `QDRANT_URL`, and its `teardown` drops only this run's leftover collections (never a concurrent run's, never an unprefixed one).
- The throwaway Qdrant never inherits `QDRANT__*` settings (`test/qdrant/launch.test.ts` › "drops inherited QDRANT__* settings but keeps the rest"); the cached executable is re-hashed against its pinned digest on every use (`test/qdrant/download.test.ts` › "verifyBinaryDigest › rejects a modified cached executable"); Docker containers carry their owner and are swept once the owner is dead (`test/qdrant/launch.test.ts` › "labels the container with its owner", "staleContainers › sweeps only containers of dead processes on this host").
