# @karmaniverous/jeeves-watcher-core

Shared Zod schemas, derived TypeScript types, defaults and constants for the [jeeves-watcher](https://www.npmjs.com/package/@karmaniverous/jeeves-watcher) ecosystem.

This package is the single source of truth for the watcher's contracts. The service validates with these schemas, and the [SDK](https://www.npmjs.com/package/@karmaniverous/jeeves-watcher-sdk) and the [OpenClaw plugin](https://www.npmjs.com/package/@karmaniverous/jeeves-watcher-openclaw) type against them, so clients cannot drift from the server.

- **Config:** `jeevesWatcherConfigSchema` and its section schemas (watch, embedding, vector store, inference rules, API key, payload indexes, sources), plus defaults such as `EMBEDDING_DEFAULTS` and `API_DEFAULTS`.
- **API:** request and response schemas for the HTTP endpoints (including the admin routes: points delete, rules register/unregister/reapply), and the client's half of the error contract: every `WATCHER_*` code an error body can carry (`WATCHER_ERROR_CODES`, type `WatcherErrorCode`) and the HTTP status each is sent with (`WATCHER_ERROR_STATUS`). The error body itself is Fastify's standard `{ statusCode, code?, error, message }` (`errorBodySchema` from `@karmaniverous/jeeves/catalog`), which the catalog's error responses use.
- **Endpoint catalog:** `WATCHER_CATALOG`, built with `defineCatalog` from [`@karmaniverous/jeeves`](https://www.npmjs.com/package/@karmaniverous/jeeves): one entry per route (29 entries, from `status` to `excludeVcsPath`), each with its verb-first name, method, path, description, auth, `kind` (`read`, `write` or `destructive`) and request and response schemas (including `watcherHealthSchema`). The entry name is the operation's one name: the SDK method, the OpenAPI `operationId` and, as `watcher_` plus the name in snake_case, the plugin tool. The `/vcs/*` entries' descriptions end with `VCS_DISABLED_NOTE`, since a server without version control answers them with a `404`. The catalog is the only route list: the service registers every route from it, and the SDK, the CLI and the plugin's tools are built from it.
- **OpenAPI:** the catalog's OpenAPI 3.1 document, `WATCHER_OPENAPI_DOCUMENT`, also published as the `@karmaniverous/jeeves-watcher-core/openapi.json` file. It is committed, regenerated by `npm run openapi` (never by the build), and a test fails when it drifts from the catalog.
- **Agent content:** `WATCHER_PROMPT_RULES` (the always-in-context rules the plugin injects) and `WATCHER_SKILL` (the plugin's `SKILL.md`, generated from `skills/jeeves-watcher/SKILL.md` by `npm run skill`, with a drift test).
- **Client key:** the API key environment variable the CLI and the plugin read (`API_KEY_ENV_VAR`, `JEEVES_WATCHER_API_KEY`).
- **Source documents:** the `<name>://<id>` reference schema (`sourceReferenceSchema`) and the callback record contract (`sourceDocumentSchema`).
- **Payload:** reserved system payload fields (`RESERVED_PAYLOAD_FIELDS`, `isReservedPayloadField`).

ESM only, Node.js >= 24.22.2. Most applications should use the SDK rather than depend on this package directly.

## Install

```bash
npm install @karmaniverous/jeeves-watcher-core
```
